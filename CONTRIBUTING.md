# Contributing

Thanks for helping keep **Awesome AI Coding Tools** useful. This list is deliberately focused, so please read the scope before opening a pull request.

## Scope

This list covers **AI tools that write, edit, and reason about code with you**.

**In scope**
- AI coding agents and CLIs (terminal, desktop, and cloud agents)
- AI-enhanced code editors and IDEs, and AI editor extensions
- Code completion and code generation assistants
- Self-hosted and local-model coding tools
- Codebase chat, search, and explanation tools aimed at working in a repository

**Out of scope**
- Agent orchestrators, parallel agent runners, and multi-agent swarms
- MCP servers, skills, plugins, and other agent extensions
- Prompt-to-app and prompt-to-site builders, and design-to-code tools
- Code review, testing, security, documentation, and observability tools
- Personal assistants and general-purpose agents
- Generic AI products without a clear developer use case

If your tool is out of scope, it is not a judgment on its quality. It belongs in a different list.

## Requirements

A tool must meet all of these to be listed:

- **Public and usable.** It has an official website, documentation page, or public repository, and people can actually use it today.
- **Maintained.** The project is not archived, shut down, or acquired and discontinued. Repositories should show recent activity.
- **Clear developer use case.** The description explains what a developer can do with it.
- **Not already listed.** Search the README for the name and URL before adding.

## Entry format

Add one entry to the **Tools** section in the existing format:

```
**[Tool Name](https://example.com/)** - Brief description.
```

- Place the entry in **alphabetical order** (case-insensitive) with a blank line before and after it.
- Use the tool's official name and capitalization.
- Link to the official site or repository. **Do not add tracking parameters** such as `utm_source`, referral codes, or affiliate links.
- Write one to two sentences. Be concise, neutral, and specific: state what the tool does and its key capabilities.
- Avoid marketing language ("best", "revolutionary", "leading", "powerful"), pricing claims, and vague taglines like "An AI code assistant."
- Mention important constraints plainly, such as closed source or paid-only, when they matter to readers.
- Do not add the same tool twice or add it to more than one place.

## Disclosure

If you built or are affiliated with the tool, say so in the pull request description. Affiliated submissions are welcome if they meet every requirement above.

## Pull request process

1. Fork the repository and create a branch.
2. Edit only `README.md` and add or change only the entries you are submitting.
3. Open a pull request with a short explanation of why the tool belongs in this list.
4. Be ready to adjust the description or position. Maintainers may reword entries to keep the list consistent.

Pull requests that are out of scope, duplicate an existing entry, or break the format may be closed with a short comment.

## Fixing existing entries

Pull requests that fix dead links, update outdated descriptions, or remove discontinued tools are very welcome. Please include a source, such as the project's announcement or repository status, when removing an entry.

## Suggesting a tool without a pull request

You can open an issue instead. Include the tool name, official link, a one-line description, and why it fits the scope above.

## Code of conduct

Be respectful and constructive. Keep discussion focused on whether and how a tool fits the list.
